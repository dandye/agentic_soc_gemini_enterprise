## 1. What is Emotet? (Threat Actor Profile)
* **Alternative Names**: Heodo, Geodo.
- **Primary Function**: Historically a banking Trojan (first observed in 2014), Emotet evolved into a highly lucrative **Botnet-as-a-Service / Infrastructure-as-a-Service (IaaS)**.
- **Operational Strategy**: Instead of acting as a standalone data thief, Emotet serves as an **initial access loader**. Its operators sell space on infected victim systems to other cybercrime groups. It primarily distributes payloads for **TrickBot, QakBot, BazarLoader, and IcedID**, which frequently act as second-stage loaders culminating in high-impact ransomware infections (e.g., **Ryuk, Conti, BlackBasta**).

---

## 2. How Does Emotet Spread? (Delivery Vectors)
Emotet employs highly effective and multi-staged social engineering campaigns to achieve initial execution:

* **Mass-Spam & Phishing (T1566)**: Large-scale spam emails containing malicious attachments or URLs.
* **Email Thread Hijacking (T1114)**: Emotet uses a specialized mail-harvesting module to scrape existing emails and contact lists from compromised systems. It then sends replies to legitimate, ongoing email threads containing a malicious attachment. Because the recipient recognizes the sender and context, the click-through success rate is exceptionally high.
* **Malicious Attachments (T1566.001)**:
  - **MS Office Documents (`.xlsm`, `.doc`, `.xls`)**: Contain highly obfuscated VBA macros.
  - **Container Files (`.zip`, `.iso`, `.vhd`)**: Used to wrap malicious payloads. This allows the file to bypass **Mark-of-the-Web (MOTW)** controls when extracted locally, bypassing smart filters.
  - **LNK and OneNote Files**: Heavily used to execute background PowerShell downloaders.
* **Template Injection (T1221)**: In some variants, the initial Word/Excel attachment has no macro code inside. Instead, it abuses OOXML template properties to fetch an external template from a remote server when opened, which then loads the malicious macros dynamically to evade static scanning.
* **Internal Self-Spreading (Worm Capabilities)**:
  - **Removable Media & Mapped Drives**: Spreading via USBs and mapped directory locations.
  - **Network Enumeration & Brute Force (T1135)**: Scanning local networks for SMB shares and attempts brute-forcing credentials.
  - **WiFi Spreader**: Historically possessed a module to harvest adjacent wireless network profiles and infect systems across adjacent networks.

## 3. Emotet’s Multi-Stage Execution Chain
Once a victim opens an attachment, the execution flows as follows:

```
[Phishing Lure/Document] ──(VBA Macro/Macro-less LNK)──> [PowerShell Cradle / JS Loader]
                                                                     │
                                                           (HTTP GET to C2 Server)
                                                                     ▼
[Target Process (eg. Explorer)] <──(Process Injection)── [Second-Stage DLL Payload]
                                                                     │
                                                          (Executed via Rundll32)
                                                                     ▼
                                                       [C2 Beaconing / Payloads Drop]
```

1. **User Execution (T1204)**: Victim opens document and is socially engineered to "Enable Content."
2. **First-Stage Downloader (T1059)**: VBA macro executes PowerShell (T1059.001) or a JavaScript downloader (e.g., `Unidentified JS 003`).
3. **Payload Retrieval (T1105)**: First-stage script contacts a series of compromised web servers to retrieve the core Emotet loader (an obfuscated/packed DLL).
4. **System Binary Proxy Execution (T1218)**: Emotet executes the DLL using standard, Microsoft-signed utilities like **`rundll32.exe` (T1218.011)** or **`regsvr32.exe` (T1218.010)** to bypass application blocklists.
5. **Process Injection & Persistence (T1055)**: Emotet injects itself into user-space processes (like `explorer.exe`) or registers itself as a Windows Service/Registry Run key (`HKCU\...\Run`) to survive system reboots.

## 4. Key Tactics, Techniques, and Procedures (TTPs)
Based on Google Threat Intelligence analysis, Emotet leverages a wide spectrum of ATT&CK techniques:

- **Defense Evasion (TA0005)**:
  - **T1497 / T1497.001 (Sandbox Evasion)**: Actively checks for virtual machines (VMware, Xen), checks if a debugger is attached (`IsDebuggerPresent`), and monitors mouse movement before running.
  - **T1027 / T1027.002 (Obfuscation & Software Packing)**: Uses custom obfuscation and high-entropy packers (like UPX/MPRESS) to change binary hashes and hide strings.
  - **T1027.007 (Dynamic API Resolution)**: Resolves Windows API calls dynamically at runtime using custom string hashes rather than linking them statically, hiding malicious functionality from automated import scans.
  - **T1574.002 (DLL Side-Loading)**: Plants malicious DLLs alongside benign, signed binaries to hijack normal program execution.
- **Credential Access (TA0006)**:
  - **T1056.001 (Keylogging)**: Polls keystrokes via native Windows APIs to steal passwords.
  - **T1555.003 (Credentials from Web Browsers)**: Extracts usernames, passwords, and sessions from common browsers (Chrome, Edge, Firefox).
  - **T1539 (Steal Web Session Cookie)**: Targets cookies to bypass Multi-Factor Authentication (MFA).
- **Discovery (TA0007)**:
  - **T1614.001 (System Language Discovery)**: Exits immediately if system language/keyboard layouts match specific locales (CIS countries) to avoid local regulatory or legal issues.
  - **T1518.001 (Security Software Discovery)**: Enumerates processes to check for anti-virus and security solutions.
- **Command & Control (TA0011)**:
  - **T1071.001 (Web Protocols)**: Communicates with its C2 servers over HTTP/HTTPS on standard and non-standard ports (e.g., `8080`, `7080`).
  - **T1573 (Encrypted Channel)**: Employs elliptic-curve cryptography (ECC) for C2 key exchange and RC4/AES for packet encryption.

## 5. Defensive & Detection Recommendations
To defend against Emotet, organizations should implement the following telemetry rules:

1. **Restrict Macro Execution**: Block Office macros entirely via GPO for files downloaded from the internet.
2. **Audit Parent-Child Process Spawns**: Use EDR to alert on Microsoft Office applications (Word, Excel) spawning processes like `cmd.exe`, `powershell.exe`, `regsvr32.exe`, `rundll32.exe`, or `wscript.exe`.
3. **Monitor Signed Binaries**: Alert on `rundll32.exe` and `regsvr32.exe` initiating network connections, particularly to non-standard ports or external IP addresses directly.
4. **Credential Theft Protections**: Restrict unbacked memory allocations and monitor LSASS access or browser profile folder reads by non-browser binaries.
